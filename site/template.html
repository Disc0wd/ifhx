The whole suite, one command.

ifhx installs, updates and removes the IFHX tools: @@NAMES_PROSE@@. Every download is checksum-verified before it replaces anything, and ifhx updates itself the same way.

Real output from a fresh home directory: both tools installed as checksum-verified prebuilt binaries.

# get ifhx once, then it manages everything (and itself)
curl -fsSLO @@REPO@@/releases/latest/download/ifhx-x86_64-linux
curl -fsSL  @@REPO@@/releases/latest/download/ifhx-x86_64-linux.sha256 | sha256sum -c -
install -Dm755 ifhx-x86_64-linux ~/.local/bin/ifhx

Or build it: cargo install --git @@REPO@@. Linux, x86_64 binaries (for other platforms, --source builds from source).

The tools.

This list is generated from registry.toml, the same file ifhx reads, so it can never drift from what you can actually install.

    @@TOOLS@@

Eight commands.

ifhx install <tool>…Install tools from a verified prebuilt binary
ifhx update [<tool>…]Update tools (default: all) and ifhx itself
ifhx updatesSee what has a newer release, change nothing
ifhx list / availableWhat is installed / everything in the registry
ifhx info <tool>Details, installed version, latest release
ifhx remove <tool>…Remove a tool's binary (its own settings are kept)
ifhx syncRefresh the tool registry now

Scripts get plain, tab-separated output and distinct exit codes; --yes is required when there is no terminal.

Careful by default.

  • Verified before it replaces anything.A binary is downloaded next to its destination, checked against the SHA-256 published in the same release, and only then moved into place in one atomic step.
  • A failure changes nothing.A bad checksum, a dropped connection or a crash leaves the version you had exactly as it was, and the install record is only updated after the file is in place.
  • It never builds code behind your back.If a release has no prebuilt file for your system, ifhx says so and stops. Building from source only happens when you pass --source, since that runs the project's own build scripts.
  • It will not overwrite what it did not install.A file already at the destination that ifhx did not put there, or one you edited afterwards, is left alone.
  • Works offline.The tool list comes from a fresh cache, the network, a stale cache, or a copy compiled into ifhx, in that order, so it never fails just because GitHub is unreachable.
  • Updates itself last.ifhx update updates every tool and then replaces ifhx itself, which is safe on Linux because the swap is a rename.
  • Honest about limits.The checksum travels with the release, so it catches corruption, not a compromised repository. Signed releases would be the next step, and the registry is only as trustworthy as this repository's main branch.

Adding a tool takes four lines.

Publish GitHub Releases tagged vX.Y.Z with a binary named <bin>-x86_64-linux and its .sha256. The release workflow in each IFHX repo does this when you push a version tag.

Then add the tool to the registry. It appears on this page, in ifhx available and in ifhx install for everyone, without a new ifhx release.

# registry.toml
[tools.ifhz]
repo = "Disc0wd/ifhz"
description = "What it does"
